# Brand AI-Readiness Audit Marketplace

A modular auditing toolkit that evaluates how well a website is prepared for discovery and engagement by AI systems — search engines, LLM-based assistants, autonomous agents, and AI crawlers.

## What It Does
This marketplace crawls a target website, runs 9 independent audit checks concurrently, and produces a single consolidated JSON report with severity-ranked findings and actionable recommendations. It evaluates a site's AI readiness, focusing on semantic markup, machine-readable structures, content accessibility, and intent continuity.

## Architecture & How Skills Compose

The marketplace is orchestrated via a central runner (`audit-orchestrator`) that dispatches URLs to individual skills. The skills compose by utilizing shared scraped and cached data generated by the orchestrator.

1. **Crawl & Cache**: The orchestrator crawls up to a set number of pages and saves the raw HTML and a `cache_index.json` manifest to a local `.audit_cache_<domain>` directory.
2. **Evidence Gate**: The orchestrator classifies the quality of the crawl (e.g., identifying bot challenges, blocked pages, access denied).
3. **Concurrent Execution**: The orchestrator invokes registered skills concurrently via subprocesses, passing `--url` and `--cache-dir`.
4. **Skill Autonomy**: Each skill reads the shared cache, evaluates its own logic, and outputs a JSON array of findings to stdout.
5. **Aggregation**: The orchestrator collects, deduplicates by ID, ranks by severity, and compiles the final report.

```
marketplace.json          ← Registers all skills
│
├── audit-orchestrator    ← Entrypoint: resolves URL, crawls, dispatches checks, compiles report
│
├── network-accessibility-audit ─┐
├── feed-syndication-audit       │
├── crawl-render-audit           │
├── entity-graph-validator       ├── 9 independent audit skills (run concurrently)
├── category-isolation-audit     │
├── content-extractability-audit │
├── intent-continuity-audit      │
├── local-omnichannel-audit      │
├── content-freshness-audit    ──┘
│
└── utils/evidence_gate.py  ← Shared page-evidence classification logic
```

## Skills Registry

Every skill defined in `marketplace.json`:

- **audit-orchestrator**: **ENTRYPOINT**. Resolves the target URL, crawls the site, performs unified evidence gating, dispatches all other audit checks concurrently, and compiles the final report.
- **network-accessibility-audit**: Checks `robots.txt` directives against AI/search bots, validates TLS health, HTTP security headers, and domain redirection patterns.
- **feed-syndication-audit**: Detects and validates RSS/Atom feeds and XML sitemaps to ensure machine-readable URL and content exposure.
- **crawl-render-audit**: Audits whether pages render usable HTML payload content for non-JavaScript crawlers; detects bot-challenge walls, empty interstitials, and heavy client-side rendering dependency.
- **entity-graph-validator**: Evaluates the core entity data (Organization/Brand) and Product schema coverage, checking for naming consistency, sameAs link coverage, and malformed JSON-LD syntax.
- **category-isolation-audit**: Evaluates category/listing pages for distinct boundaries by checking for thin descriptive copy, near-duplicate text between sibling categories, and heavy product cross-listing that cannibalizes semantic intent.
- **content-extractability-audit**: Scans for informational content locked inside non-semantic UI elements without text fallbacks (e.g., images lacking alt text, canvas/SVG elements without accessible descriptions, video without captions, and data tables as images).
- **intent-continuity-audit**: Evaluates site structure, overlays, deep-linking anchors, above-fold transactional density, meta descriptions, title uniqueness, and presence of conversion endpoints/CTAs to ensure AI-driven traffic maintains intent.
- **local-omnichannel-audit**: Validates physical store presence for AI discoverability. Checks for LocalBusiness/Store schema, PostalAddress completeness, GeoCoordinates, NAP consistency across pages, and whether store locators are locked in JS widgets.
- **content-freshness-audit**: Audits freshness signals by checking for `dateModified`/`datePublished` in JSON-LD, outdated footer copyright years, and `sitemap.xml` `<lastmod>` timestamps to prevent AI temporal hallucinations.

## How to Run / Usage

**Prerequisites:**
- Python 3.10+
- Dependencies installed via `pip install -r requirements.txt` (`requests`, `beautifulsoup4`)

To run the marketplace, invoke the entrypoint skill (`audit-orchestrator`):

```bash
python skills/audit-orchestrator/scripts/compile_report.py --url <url>
```

**Expected Input:** 
A target `--url` which can be a bare domain (e.g., `example.com`), a full URL (e.g., `https://www.example.com/`), or a specific internal page.

**Expected Output:** 
A consolidated JSON report printed to stdout.

**Example:**
```bash
python skills/audit-orchestrator/scripts/compile_report.py --url example.com > report.json
```

## Report Structure

The generated JSON report contains the following key sections:
- `site`: The audited URL/domain.
- `audited_at`: ISO 8601 timestamp of the audit.
- `audit_confidence`: Confidence levels based on execution success and evidence quality.
- `crawl_summary`: Details on pages requested, usable pages, and challenge ratios.
- `summary`: Counts of actionable findings grouped by severity (critical, high, medium, low).
- `findings`: A list of actionable defects and recommendations sorted descending by severity. Each finding contains an `id`, `title`, `severity`, `evidence`, and `suggested_action`.
- `audit_notes`: Informational diagnostics, passes, and non-actionable findings (severity: info).

## Safety & Read-Only Behavior

The marketplace executes strictly **read-only** and **recommend-only** operations. 
- It acts purely as an external diagnostic crawler utilizing standard HTTP GET requests.
- It respects `robots.txt` crawl-delays and implements a strict maximum page limit to minimize server footprint.
- It will never submit forms, log in, mutate data, or perform destructive actions on a live site.

## Testing & Validation

A `test_urls.txt` file is included in the root directory for testing purposes. You can validate the tool's functionality by running the orchestrator against the sample domains listed in this file.

## Runtime Assumptions

- A functional network connection with DNS resolution is available.
- Target endpoints support standard HTTP/HTTPS protocols.
- The runtime environment has Python installed along with all dependencies in `requirements.txt`.
- Sub-skills can access the local filesystem to read the cache generated by the orchestrator (`--cache-dir`), which is essential for ensuring consistency and preventing redundant network requests.
