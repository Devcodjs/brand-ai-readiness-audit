# audit-orchestrator

## When to use
This is the **primary entrypoint** for the marketplace. Users should invoke this skill to execute a full AI-readiness audit against any target website.

## Inputs
- `--url` (string): The target website URL to audit. This is the only required input.

## Procedure
1. **How audit enters**: The user invokes `compile_report.py --url <target_url>`.
2. **URL validation**: The orchestrator validates the target URL and determines the base domain for crawling.
3. **Caching**: A local `.audit_cache_<domain>` directory is created.
4. **Crawling**: `SiteCrawler` executes, traversing up to 12 pages, respecting `robots.txt`, and saving HTML payloads and `cache_index.json`.
5. **Evidence classification**: `evidence_gate.py` runs synchronously to classify the quality of the crawl (identifying bot challenges, blocked pages, etc.).
6. **Skill invocation**: The orchestrator queries `marketplace.json` (or hardcoded defaults) and invokes eligible skills concurrently via `ThreadPoolExecutor` as independent subprocesses.
7. **Skill suppression logic**: `ALWAYS_SAFE_SKILLS` run regardless of crawl quality. `PAGE_DEPENDENT_SKILLS` are suppressed if the crawl yielded too few usable pages (<3 usable pages and <40% usable ratio) to prevent false-positive hallucinations.
8. **Data flow**: The orchestrator passes the `--url` and `--cache-dir` arguments to each skill script. Skills read from the cache and output JSON to `stdout`.
9. **Deduplication**: Findings from all skills are aggregated and deduplicated based on the `id` field.
10. **Report construction**: Findings are sorted by severity. `critical`, `high`, `medium`, and `low` findings are placed in the `findings` array. `info` level findings are segregated into the `audit_notes` array. The orchestrator injects the `"skill"` field into every finding to track its origin.

## Output
Outputs a comprehensive JSON report to standard output containing:
- `site`: The audited domain.
- `audited_at`: ISO 8601 timestamp.
- `audit_confidence`: High/Medium/Low based on execution success.
- `crawl_summary`: Stats on the crawl phase.
- `summary`: Counts of findings by severity.
- `findings`: Array of actionable defects (Critical to Low).
- `audit_notes`: Array of informational findings and passes.

**Detection Logic:**
The orchestrator itself detects overall site accessibility and crawlability:
- **SYS-ERR-***: Identifies skill execution failures or crashes.
- **EVIDENCE-GATE**: Classifies the overall crawl quality (usable, challenge-blocked, connection-failed).

**Severity:**
The orchestrator calculates an overall `audit_confidence` based on the percentage of successful skill executions and the ratio of usable crawled pages. It sorts findings strictly by severity: `critical` -> `high` -> `medium` -> `low`.

**Suggested Actions:**
N/A - The orchestrator does not emit domain-specific findings. It passes through the suggested actions generated by the downstream skills. If a skill crashes, the orchestrator injects an internal error finding directing the user to check the skill implementation.
